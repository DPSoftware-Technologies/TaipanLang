# Taipan

A game scripting language built as a modern replacement for Lua: brace blocks
with Python-style readability, static types with an explicit `any` escape
hatch, null safety, built-in coroutines, hot reload, and Rust-style error
messages. It runs on a bytecode VM with an incremental, generational GC. The
implementation is plain C++17 with no dependencies.

**To learn the language, read [docs.md](docs.md)**, the complete programming guide.
The language design lives in [taipandesign.md](taipandesign.md). This README
covers how to build, use, embed and change the implementation. Release notes:
[CHANGELOG.md](CHANGELOG.md).

```
func calculateDamage(int base, float multiplier) -> int {
    return base * multiplier
}

coroutine enemyPatrol(entity e) {
    while true {
        e.moveTo(pointA)
        wait(2.0)
        e.moveTo(pointB)
        wait(2.0)
    }
}

start enemyPatrol(goblin)
```

---

## 1. Build

Any C++17 compiler works (GCC 9+, Clang 10+, MSVC 2019+). Pick one:

| How | Command |
|---|---|
| One line, any compiler | `g++ -std=c++17 -O2 -Iinclude src/*.cpp tools/taipan_main.cpp -o taipan` |
| Script (Linux / macOS / Git Bash) | `./build.sh` (or `./build.sh debug`) |
| Script (Windows) | `build.bat` (MSVC if `cl` is on PATH, else MinGW `g++`) |
| CMake | `cmake -S . -B build && cmake --build build` |

The scripts and CMake also build `taipan-lsp`, the language server (see
[Editor support](#editor-support-lsp)). CMake additionally builds `taipan_lib`
(a static library for your engine), the `embed_demo` example and the
`api_test` self-test (`ctest`).

## 2. Run

```
taipan script.tp            run a script (coroutines keep running until they finish)
taipan --check script.tp    type-check only
taipan --disasm script.tp   show the generated bytecode
taipan --help               all options
```

Try `taipan examples/hello.tp` and `taipan examples/game_demo.tp`.

### Performance test

`taipan examples/benchmark.tp` times 14 workloads:

- recursive calls
- integer and float math, including native calls
- strings
- lists, sorting, dicts
- method calls
- object allocation (garbage-collector churn)
- closures, filter/map
- throw/catch
- 2000 coroutines resumed once per frame

It also checks every result. Raise `SCALE` at the top of the file for longer
runs, and add `--gc-stats` to see what the garbage collector did.

Against Lua 5.4.7 built with the same compiler (`tests/perf/core.tp` /
`core.lua`, best of 7, GCC 16 `-O2`, Windows x64):

| | Taipan | Lua 5.4 |
|---|---|---|
| fib(27) | 11.2 ms | 7.0 ms |
| 5M-iteration integer loop | 33.5 ms | 30.0 ms |
| 1M method calls | 39.9 ms | 38.0 ms |
| 1M calls to a built-in native | 24.0 ms | 16.0 ms |
| 1M calls to a host C++ function (`tests/perf/host_bench.cpp`) | 25.4 ms | 18.0 ms |
| 1M calls to a bound C++ method | 26.1 ms | 64.0 ms |
| 1M reads of a bound C++ property | 18.2 ms | 30.0 ms |

MSVC has no computed goto, so its build uses a `switch` and is slower (int
loop 62 ms vs 38 ms for MSVC-built Lua). In an MSVC project, compile Taipan's
sources with **clang-cl** (MSVC-compatible objects) to get the faster loop.

## 3. Language tour

Comments are `//` and `/* */`. A statement ends at the newline (use `;` to put
several on one line). Newlines inside `()`, `[]` and dict literals are
ignored, and a trailing `\` continues a line. Indentation has no meaning;
braces define blocks.

### Variables, types, constants

```
int x = 5
float speed                // zero value: 0.0  (int 0, bool false, str "", [] , {})
str name = "goblin"
const int MAX_HEALTH = 100 // reassigning it is a compile error
any anything = 1           // the only dynamically typed variables
anything = "fine"

int? maybe = null          // only `T?` types may hold null
if maybe != null {
    print(maybe + 1)       // narrowed to int inside the check
}
int value = maybe ?? 0     // null coalescing
```

Every declaration states its type (no inference). `list<T>` and `dict<K, V>`
are the generic containers. `enable ExtType` unlocks `int8`..`int64`,
`uint8`..`uint64` (`byte` = `uint8`), `f32` and `f64`. Values are wrapped or
rounded to the width when stored, and out-of-range literals are compile errors.

### Functions

```
func heal(entity target, int amount = 10) {     // no arrow = returns nothing
    target.hp += amount
}

func getPlayerStats() -> (int, int) {            // multiple return values
    return hp, mana
}
int health, int mana = getPlayerStats()

func logMessage(str prefix, any... args) {       // variadic: args is list<any>
    for any a in args { print(prefix + a) }
}

func onDeath(func callback) { callback() }       // functions are values
enemies.forEach((entity e) -> { e.update() })    // lambdas
list<any> doubled = numbers.map((int n) -> n * 2) // expression-bodied lambda
```

### Control flow

```
if hp <= 0 { die() } else if hp < 20 { flee() } else { fight() }

for int i in range(10) { }                  // range(end) / range(start, end[, step])
for entity e in enemies { }
for (int index, entity e) in enemies { }    // index + item
for (str key, int value) in scores { }      // key + value
for (int i = 0; i < 10; i++) { }            // C-style escape hatch
while a < 50 { a += 1 }

match state {                               // no fallthrough
    PlayerState.IDLE -> { print("standing still") }
    PlayerState.WALKING, PlayerState.RUNNING -> print("moving")
    else -> { print("other") }
}

try {
    riskyOperation()
} catch error {
    print("something broke: " + error)
}
throw "custom error"                        // any value can be thrown
```

### Classes, interfaces, enums

```
interface Damageable {
    func takeDamage(int amount)
}

class Enemy implements Damageable {          // no inheritance: use composition and interfaces
    int hp = 100                             // public by default
    private str internalName = "goblin_01"
    Enemy? target                            // class-typed fields must be nullable or initialized

    func init(int startHp) {                 // optional constructor: Enemy(50)
        hp = startHp
    }

    func takeDamage(int amount) {
        hp -= amount                         // members need no `this.` (it is allowed)
        logDamage(amount)
    }

    private func logDamage(int amount) {
        print("took " + amount)
    }
}

enum PlayerState { IDLE, WALKING, ATTACKING, DEAD }
PlayerState s = PlayerState.IDLE             // s.name == "IDLE", s.index == 0

class Vec2 {
    float x
    float y
    static Vec2 zero = Vec2(0, 0)            // one per class: Vec2.zero
    func init(float ax, float ay) { x = ax; y = ay }
    operator +(Vec2 o) -> Vec2 { return Vec2(x + o.x, y + o.y) }
    operator *(float k) -> Vec2 { return Vec2(x * k, y * k) }
    static func dot(Vec2 a, Vec2 b) -> float { return a.x * b.x + a.y * b.y }
}
Vec2 p = Vec2.zero + Vec2(1, 2) * 3.0
```

Classes, lists and dicts are reference types. Strings are immutable.

### Coroutines

```
coroutine countdown(int n) {
    while n > 0 {
        print(n)
        n -= 1
        wait(1.0)      // yields to the host and resumes 1 second later; wait() = next frame
    }
}
any task = start countdown(3)   // runs until its first wait()
task.stop()                     // task.isRunning() checks it
```

Coroutines are cooperative and single-threaded. The host advances them with
`taipan_update(state, dt)`, and the standalone runner uses the real clock.

### Modules

```
import enemies.ai              // scripts/enemies/ai.tp
import player.ai as playerAI   // alias
import helpers                 // bare name: must match exactly one helpers.tp under the root

enemies.ai.updateAll()
playerAI.handleInput()
```

You always access members as `module.member`. The standard library and the
host's native bindings never need `import`. Circular imports are compile
errors.

### Standard library

| Always available | Standalone runner only (blocking or unrestricted I/O) |
|---|---|
| `print(...)`, f-strings `f"hp {hp}"` | `input(prompt)` |
| `toInt` `toFloat` `toStr` `toBool` `typeOf` `range` | `time.sleep(seconds)` |
| `math.abs min max floor ceil round sqrt pow sin cos tan atan2 clamp lerp random randomInt seed pi` | `file.read write append exists` |
| `str.length toUpper toLower split trim contains replace startsWith endsWith indexOf sub repeat` (also as methods: `s.toUpper()`) | |
| `json.parse` `json.stringify`, `time.now` `time.clock` `time.scriptTime` | |
| list: `add insert removeAt remove pop contains indexOf clear forEach map filter sort reverse slice join copy isEmpty length` | |
| dict: `keys values has remove get(key, default) clear copy isEmpty length` | |

### Error messages

```
error: type mismatch
  --> game.tp:3:13
   |
 3 |     int x = "hello"
   |             ^^^^^^^ expected 'int', found 'str'

error: possible null reference
  --> game.tp:12:5
   |
12 |     target.takeDamage(10)
   |     ^^^^^^ 'target' is type 'Enemy?' (nullable) - check for null before use
```

The checker reports `error:` for problems that block execution and
`warning:` for unused variables, unreachable code, non-exhaustive enum
matches and truncating `float` to `int` conversions. Runtime errors use the
same format and add a traceback.

## 4. Embedding in an engine

Include `include/taipan.h` and compile `src/*.cpp` into your project, or link
`taipan_lib`.

```cpp
#include "taipan.h"

TaipanValue native_spawn(TaipanArgs args) {           // every native has this signature
    Entity* e = World::SpawnAt(args.getString(0), (int)args.getInt(1), (int)args.getInt(2));
    return TaipanValue::fromObject("Entity", e);       // engine keeps ownership
}

int main() {
    TaipanState* state = taipan_create();

    taipan_register_class(state, "Entity")
        .alias("entity")                               // script may write `entity`
        .property("hp", &Entity::hp)
        .method("takeDamage", &Entity::takeDamage);
    taipan_register_function(state, "engine.spawn", native_spawn, "(str, int, int) -> Entity");

    taipan_load_file(state, "enemy_ai.tp");            // compile + type-check
    taipan_run(state);                                 // run top-level code
    taipan_call_function(state, "onPlayerDeath");

    while (running) taipan_update(state, dt);          // resume coroutines each frame

    taipan_reload_file(state, "enemy_ai.tp");          // hot reload
    taipan_destroy(state);
}
```

Things to know:

- **Ownership.** Native objects stay owned by the engine; scripts hold
  handles. Call `taipan_invalidate_object(state, ptr)` when an object dies.
  After that, script use of the handle is a catchable error
  (`use of invalid Entity handle`), not a crash.
- **Signatures** for functions (`"(str, int=) -> Entity"`, where `=` marks an
  optional parameter and `...` a variadic one) are optional. With one, calls
  are type-checked at load time. Class bindings made from member pointers get
  their types automatically.
- **Globals:** `taipan_get_global`, `taipan_set_global_int/_float/_bool/_string`.
- **Errors** go to `taipan_set_error_handler` (stderr by default) and
  `taipan_last_error`. `print` goes to `taipan_set_print_handler`.
- **One environment per entity:** `taipan_script_new(state, path)` creates a
  script instance with its own globals (shared bytecode), like a Lua
  environment per entity. Use `taipan_script_run` / `taipan_script_call` /
  `taipan_script_get` / `taipan_script_set` / `taipan_script_free`. Hot reload
  updates every live instance and keeps its state; freeing an instance stops
  its coroutines.
- **Threads:** one `TaipanState` is single-threaded. For multiple cores, run
  one state per thread.
- **Register before loading.** The checker needs to know your natives and
  classes when it compiles the script.
- **Standalone vs embedded.** `taipan_open_standalone` adds the blocking
  built-ins. A game usually skips it and registers sandboxed versions instead.

See [examples/embed_demo.cpp](examples/embed_demo.cpp) with
[examples/enemy_ai.tp](examples/enemy_ai.tp) for a complete working host.

### Value types (Vector3, Quaternion, Color)

Small math types should be **value types**, not handles: the script owns an
immutable copy, values compare by content, and operators, constructors and
static members make Unity-style code work as written.

```cpp
struct Vector3 { float x, y, z; /* operators, Distance, ... */ };

taipan_register_value<Vector3>(state, "Vector3")
    .constructor<Vector3(float, float, float)>()             // Vector3(1, 2, 3)
    .property("x", &Vector3::x).property("y", &Vector3::y).property("z", &Vector3::z)
    .method("magnitude", &Vector3::magnitude)
    .op("+", [](const Vector3& a, const Vector3& b) { return a + b; })
    .op("*", [](const Vector3& a, float k) { return a * k; })    // v * 2.0
    .op("*", [](float k, const Vector3& a) { return a * k; })    // 2.0 * v
    .op("-", [](const Vector3& a) { return a * -1.0f; })         // unary minus
    .op("==", [](const Vector3& a, const Vector3& b) { return a == b; })
    .staticMethod("Distance", &Vector3::Distance)               // Vector3.Distance(a, b)
    .constant("zero", Vector3 {0, 0, 0})                        // Vector3.zero
    .toString([](const Vector3& v) { return fmt(v); });         // print / f-strings

// a handle class with a value-type property: `self.position += dir * dt` works
taipan_register_class(state, "Transform").property("position", &Transform::position);

// typed free functions: the signature comes from the C++ callable
taipan_bind_function(state, "Input.GetAxis2", [](std::string axis) { return input.axis2(axis); });
taipan_bind_function(state, "Debug.Log", [](std::string msg) { engineLog(msg); });
```

- The type must be copy-constructible. Values are copied into a
  garbage-collected box on the way into the script and copied out on the way
  back (`TaipanValue::fromValue(v)`, `value.asValue<Vector3>()`,
  `args.getValue(i, "Vector3")`).
- Operators: `+ - * / % == < <= > >=` and unary `-`. A two-parameter
  callable whose first parameter is not the registered type registers the
  reversed form (`float * Vector3`). The result type is checked at compile time.
- `.staticMethod` and `.constant` also work on handle classes registered with
  `taipan_register_class`.
- Each operation allocates one small object. That is cheap, but not free: for
  thousands of entities per frame, expose bulk engine functions.

### Hot reload semantics

`taipan_reload_file` recompiles the file and re-runs only its declarations:

- Functions are replaced. Running coroutines call the new versions from their
  next call onward.
- Classes are updated in place, so live instances get the new methods. Fields
  added to a class get their zero value on existing instances.
- Global variables keep their current values; new globals are initialized.
- Other top-level statements (such as `start patrol(goblin)`) are not re-run,
  so nothing restarts.
- If the script defines `func onReload()`, it is called afterwards.

### Bytecode cache

Compiled bytecode is cached in `<temp>/taipan_cache` (like Python's `.pyc`).
An entry is used only if the source and every module it imports are
unchanged. Turn it off or move it with `taipan_set_bytecode_cache(state,
enabled, dir)`, or with `--no-cache` / `--cache-dir` on the command line.

## Editor support (LSP)

`taipan-lsp` is a language server: any editor that speaks the Language Server
Protocol gets these features for `.tp` files:

- errors and warnings as you type
- hover with types and signatures
- go to definition, including into imported modules
- completion for locals, globals, built-ins, keywords, and members after `.`
- a document outline

It uses the real type checker but never runs your scripts. Unsaved changes in
other open files are taken into account.

### VS Code

The extension lives in [editors/vscode](editors/vscode). It provides syntax
highlighting for `.tp` and `.tpi`, starts the server, and adds a
**Taipan: Run Current File** command.

```
./build.sh                                   # builds build/taipan-lsp
cd editors/vscode
npm install
mkdir -p bin && cp ../../build/taipan-lsp* bin/   # bundle the server (optional)
npx @vscode/vsce package --skip-license --allow-missing-repository
code --install-extension taipan-0.2.0.vsix
```

If you skip bundling, put `taipan-lsp` on your `PATH` or set
`taipan.server.path`. For development, open `editors/vscode` in VS Code and
press F5.

### Engine bindings (.tpi files)

A game registers natives such as `engine.spawn()` or `Entity` at runtime, so
editors and CI cannot see them. A binding stub file declares that API:

```
// engine.tpi
namespace engine {
    func spawn(str prefab, int x = 0, int y = 0) -> Entity
    float gravity
}
class Entity as entity {
    int hp
    readonly str name
    func takeDamage(int amount)
}
value class Vector3 {
    float x
    func init(float x, float y, float z)          // constructor
    operator +(Vector3 o) -> Vector3
    operator *(float k, Vector3 v) -> Vector3     // two parameters: reversed form
    operator -() -> Vector3                       // unary minus
    static func Distance(Vector3 a, Vector3 b) -> float
    static Vector3 zero
}
```

- **Generate it** from the engine, so it always matches what is actually
  registered: `taipan_dump_bindings(state, "engine.tpi")`. The
  `embed_demo` example does this.
- **The language server** loads every `*.tpi` in the workspace automatically.
  Add others with the `bindings` setting.
- **CI / command line:** `taipan --check --bindings engine.tpi enemy_ai.tp`
- **From C++:** `taipan_load_bindings(state, path)`. Stubs never replace real
  registrations. Calling a stub that the host did not register is a catchable
  `missing native` error.

Server settings (LSP `initializationOptions`, or the `taipan.*` VS Code
settings):

| Setting | Meaning |
|---|---|
| `scriptRoot` | Folder imports resolve from. Default: each file's own folder, like the standalone runner. |
| `bindings` | Extra `.tpi` files. |
| `standalone` | Whether to allow `input`, `time.sleep`, `file.*` (default `true`). |

## 5. Project layout and where to make changes

```
include/taipan.h     public embedding API (the only header a host needs)
src/internal.h       Value, heap objects, opcodes, Proto, the VM struct
src/lexer.*          tokens; newline / continuation rules
src/parser.*  ast.h  recursive-descent parser -> AST
src/types.h          static type representation
src/compiler.*       type checker + bytecode generator in one pass
src/vm.cpp           interpreter loop, calls, coroutines, try/catch, fields, type checks
src/gc.cpp           incremental + generational garbage collector
src/object.cpp       strings (interned), dict, printing, equality
src/stdlib.cpp       standard library (core + standalone-only)
src/module.cpp       loader.h: imports, bytecode cache, hot reload, disassembler
src/api.cpp          implementation of taipan.h
src/diag.cpp         Rust-style diagnostic formatting
src/bindings.cpp     .tpi binding stubs: loading and dumping
src/analysis.*       editor analysis (symbols, hover, completion) for the language server
tools/taipan_main.cpp   the standalone runner
tools/taipan_lsp.cpp    the language server (JSON-RPC over stdio)
editors/vscode/      VS Code extension: grammar, language config, LSP client
.claude/skills/taipan/  skill for AI coding agents: language reference, embedding, internals, verify.sh
examples/            hello.tp, game_demo.tp, benchmark.tp, embed_demo.cpp + enemy_ai.tp + engine.tpi
tests/               golden-output tests (run_tests.sh), api_test.cpp, lsp_test.py
```

Common changes:

- **Add a built-in function:** call `defineNative("name", fn, "(sig) -> ret")`
  in `VM::openCore` (`src/stdlib.cpp`). A host can do the same with
  `taipan_register_function`.
- **Add a list or dict method:** add the name to the table in the `VM::VM`
  constructor (`vm.cpp`), its minimum argument count in `invokeBuiltin`, the
  implementation in `builtinListMethod` / `builtinDictMethod`, and its static
  signature in `Compiler::builtinMethod`.
- **Add an operator or opcode:** add it to `TAIPAN_OPCODES` in `internal.h`
  (with its operand count), emit it in `compiler.cpp`, and execute it in
  `VM::execute`. Bump `kCacheVersion` in `module.cpp` whenever the bytecode
  format changes.
- **Add syntax:** lexer token, then parser, AST node, and a case in the compiler.
- **Tune the GC:** see `minorLimit`, `minMajorLimit`, `stepBytes` and
  `stepBudget` in `internal.h`.

### How it works

- **Pipeline:** source -> lexer -> parser -> AST -> checker/codegen (one pass,
  after hoisting top-level declarations) -> bytecode `Proto` -> stack VM.
  "Compile errors" are reported at load time, before anything runs.
- **Values:** `int`, `float`, `bool` and `null` are stored inline (no heap,
  no GC). Strings, lists, dicts, closures, instances and the rest are heap
  objects.
- **Coroutines:** each coroutine is its own `ObjThread` with its own value
  stack and call frames, so `wait()` just returns from the interpreter loop.
  Upvalues are index-based, so stacks can grow freely.
- **GC:** new objects start young. A minor collection scans the roots plus
  the remembered set (old objects the write barrier saw receive young
  references) and promotes objects that survive two minor collections. When
  the old generation doubles, an incremental major cycle runs: tri-colour
  marking and sweeping in small allocation-paced steps, a Dijkstra write
  barrier, and a short atomic phase that re-scans thread stacks. Nothing is
  reference-counted, so cycles are collected.
- **Errors:** runtime errors are C++ exceptions caught by the interpreter
  loop and routed to the nearest `try` handler on the current coroutine.
  Every instruction keeps a source span for the diagnostics.

## 6. Decisions taken where the spec left questions open

| Topic | Implemented as |
|---|---|
| Function declaration style | Arrow style: `func f(int a) -> int`. No arrow means no return value. |
| Constants | `const` keyword, enforced by the compiler. |
| Zero values of custom types | Nullable types start as `null`, enums as their first member, `func` as `null`. A non-nullable class or native type with no initializer is a compile error. |
| `int` <- `float` | Allowed with a truncation warning, so the spec's own `return base * multiplier` example compiles. `float` <- `int` converts silently. |
| `str + anything` | Converts the other operand to text, as in `"took " + damage`. |
| Calls into `any` / `func` values | Checked at runtime. Assigning an `any` to a typed variable inserts a runtime type check. |
| `import engine.types` | No-op when `engine` is a host-registered namespace. |

**Additions beyond the spec:** `throw`, an optional `init` constructor,
`this`, the `??` operator, bitwise operators, expression-bodied lambdas,
several patterns per match arm, task handles returned by `start`
(`stop()` / `isRunning()`), the `onReload()` hook, and `typeOf`.

**Known limitations / future work:**

- Strings are byte-indexed (`length`, `s[i]` and iteration are UTF-8
  unaware).
- `uint64` is stored as a signed 64-bit value.
- `func` is the only function type (no typed `func(int) -> int` yet).
- There is no user-defined generics.
- The language server covers diagnostics, hover, definition, completion and
  the outline. Rename, find references, signature help and formatting are not
  done yet.
- There is no debugger and no JIT, as the spec defers both.

## 7. Tests

```
./build.sh && tests/run_tests.sh          # golden-output tests
tests/run_tests.sh --gc-tiny              # same, with tiny incremental-GC thresholds
tests/run_tests.sh --gc-stress            # same, collecting at every safepoint
cmake --build build && ctest --test-dir build   # embedding API tests
python tests/lsp_test.py                  # language server, end to end over LSP
```

For GC debugging, build with `-DTAIPAN_GC_DEBUG` (or the CMake option
`TAIPAN_GC_DEBUG=ON`). Freed objects are then poisoned instead of deleted, so
a dangling reference aborts immediately.
